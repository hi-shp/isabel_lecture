# Isabel 위치별 용존산소 조사

ROS 2 `water_survey`는 ScienceCube WL118DO 수신값을 위치와 결합해 격자 지도와 조사 파일로 저장합니다. 이사벨 작업이며 별개 프로젝트인 `kaboat2026` 코드를 실행하거나 수정하지 않습니다.

## 목표 접근과 입력값 보존

주행 시작 때 현재 IMU 방향과 목표의 좌우 설정 각도 후보를 비교해 가까운 쪽을 먼저 선택합니다. 이후 매 제어 주기 현재 위치에서 본 목표 방위를 계산하고 정확히 입력한 각도만큼 벗어나 진행합니다. 목표에 가까워져도 각도를 추가로 벌리거나, 시작 때의 절대 방위를 고정해 목표를 지나치지 않습니다. 이상적인 방향 추종 조건에서 45°를 유지한 채 마지막 도착 반경 안으로 들어가는 자동 확인을 통과했습니다. 실제 관성·서보 응답에 따른 도착 정확도는 현장 시험 대상입니다.

입력창에서 Enter를 누르면 즉시 적용 요청을 보내며, 선박은 허용한 설정값을 /home/ubuntu/water_survey_data/settings.json에 원자적으로 저장합니다. 새 지도와 프로세스 재시작 후에도 같은 설정을 불러옵니다. 지도 확대 배율은 해당 노트북 브라우저에 저장하고 새 지도·새 창에서도 복원합니다. 위치 초기화와 현재 위치로는 확대 배율을 바꾸지 않습니다.

**현재 위치로**를 누르면 이후 선박 위치를 지도 중심이 자동 추적합니다. 확대 배율은 유지하고 지도를 직접 드래그하면 추적을 해제합니다.

## + 키로 방향 전환

자율운항 중 대시보드 창에서 **+**를 누르면 현재 목표의 반대쪽 입력 각도로 즉시 전환합니다. 일반 키보드의 Shift+=와 숫자 키패드 +를 지원합니다. 방향 전환 (+) 버튼도 같은 요청을 보냅니다. 입력창을 편집 중이거나 Ctrl/Alt/Meta와 함께 누른 키는 주행 명령으로 사용하지 않습니다. Enter는 입력값 저장에 사용합니다. 키를 누르고 있는 동안 반복 전환하지 않고 한 번 누를 때 한 번 요청합니다.

현재 버전은 라이다 장애물 감지로 방향을 바꾸지 않으며 3초 전환 대기도 사용하지 않습니다. 라이다 연결·정면 히트는 이 방식의 시작·유지 조건이 아닙니다. 라이다가 들어오면 상태 표시와 원본 기록은 계속합니다. GPS·IMU·DO 및 실제 조향·추진 인터페이스의 기존 조건은 유지합니다.

처음에는 현재 IMU 방향에 가까운 쪽을 고르고 이동 중에는 현재 목표 방위에서 정확히 입력한 각도를 유지합니다. 센서 지연 또는 마지막 도착으로 조사 파일을 자동 종료하지 않고, 필요한 입력이 없으면 중립 대기합니다. 마지막 경유지에서도 중립으로 기록을 계속하며 주행 종료 버튼이 파일을 마감합니다. 종료 후 늦게 도착한 전환 요청은 거부하고 동일 요청이 중복 도착해도 한 번만 전환합니다.

자동 확인 63개 통과. 라이다 없음·무효·단절 상태의 시작과 주행, 장애물만으로 전환하지 않음, 연속 키 요청의 즉시 좌우 전환, 요청 중복 방지 및 종료 후 전환 거부를 포함합니다. 실제 강의 전체 주행 정확도를 확인한 것은 아닙니다.

NTRIP 보정과 실제 실외 GPS 좌표 수신은 확인했습니다. RTK FIX 정확도는 아직 별도 확인 대상입니다. 라이다는 USB 인식 오류로 복구 대기 중이며 + 키 방식으로 변경했습니다.

## 센서 표시·선수 방향·전체 브링업

상단에는 현재 제어에 사용하는 GPS 위도·경도, 라이다 정면 거리·점 수·수신률, IMU 선수 방위·롤·피치·수신률을 표시합니다. 수동 GPS를 찍으면 같은 GPS 표시에서 그 좌표를 즉시 보여줍니다. 수신 지연·무효값은 별도로 표시하고 지그재그 주행 중에는 목표 방위·IMU 편차·조향 명령도 확인할 수 있습니다. 화면 캡처·녹화 버튼은 제거했으며 센서 자동 기록은 계속됩니다.

지도 선박은 실제 IMU 방위를 따르는 화살표이며, 현재 위치로 버튼은 확대 배율을 바꾸지 않고 지도 중심만 이동합니다. 상단·입력·버튼·패널 간격을 압축하고 지도 높이는 화면에 따라 540~820px로 조정했습니다.

전체 브링업·재시작 버튼은 먼저 중립을 발행하고 기존 관리 서비스의 전체 프로세스를 종료한 뒤 새로 띄웁니다. 같은 사용자의 서비스 밖 mechaship_bringup 중복 실행 트리만 정리하며 다른 패키지·대시보드·기록 서비스는 정리 대상이 아닙니다. 처리 중 중복 요청은 거부하고 새 서비스 PID로 실행 전환을 확인합니다. 재시작 뒤 주행을 자동으로 재개하지 않습니다.

경유지 추가·드래그·조사 시작·직사각형 지정의 2km 제한을 제거했습니다. 좌표 형식·격자 수의 메모리 제한은 유지합니다. 자동 확인 63개 통과. 실제 서보90→70→110→90° 단독 시험에서 사용자가 움직임을 확인했습니다. IMU 편차가 목표 양쪽 ±20°일 때 조향 명령이110°/70°로 바뀌고 동일 목표 방위의 IMU 편차를 교정하는 회귀 시험도 통과했습니다. 이전 주행 로그에서도 조향84.8~150° 발행을 확인했으며 선체 전체 회전 성능과 구분합니다.

## 수동 GPS와 실제 추진

가상위치 퍼블리시는 위치 입력만 대체합니다. **웨이포인트 주행** 또는 **자율운항 주행**은 별도 추진 선택 없이 실제 센서·조향·추진기를 사용합니다. **주행 종료**는 중립을 발행합니다. 수동 위치와 장치 GPS는 같은 좌표 표시를 쓰며 출처만 구분합니다. 실제 센서 위치를 덮어쓰지 않고 기록에는 수동 위치 출처를 보존합니다.

브링업 후 첫 유효 IMU 방위를 사용자가 지정한 북쪽0°로 잡습니다. 이후 상대 회전각을 지그재그 목표 유지와 지도 화살표에 사용합니다. 기준값은 heading-reference.json과 조사 메타데이터에 저장합니다.

새 조사 지도는 현재 GPS 입력을 유지하고 그 위치를 기본 중심으로 사용합니다. 현재 위치로·지도 보기 초기화는 확대 배율을 바꾸지 않습니다. 연결 안내·조작 설명·준비 안내와 캡처/녹화 버튼은 제거하고 세로 간격을 줄였습니다.

NTRIP은 비공개 파일 ~/.config/isabel/ntrip.yaml의 계정을 사용합니다. 계정 정보는 저장소에 넣지 않습니다. 기존 vendor launch에는 scripts/configure_ntrip_seed.py로 NTRIP 입력 토픽 인자를 추가합니다. water-survey-ntrip-seed.service는 선택된 GPS 또는 마지막 유효 위치를 VRS 초기 위치로만 전달하며 /gps/fix의 실제 측정값은 수정하지 않습니다. RTCM 수신과 실제 수신기의 RTK FIX 판정은 별개입니다.

핫스팟에서 기존 SSH 키가 일치하는 이사벨 Radxa ROCK 5A를 다시 찾아 적용했습니다. 현재 버전은 `/home/ubuntu/water_survey_releases/20261125_1431/`, 고정 연결은 `/home/ubuntu/water_survey_ws/current_release`입니다. 기존 코드·서비스는 `/home/ubuntu/water_survey_backups/20261125_1431/`에 백업하고 이전 조사 자료를 보존했습니다. 서비스는 SSH와 독립적으로 실행합니다.

선박 빌드와 자동 확인 43개 통과. 실제 WL118D283/V403 DO로 4칸/13개 조사 및 재접속 확인. 실제 DO·IMU·라이다를 사용한 클릭 위치 주행에서 출력·반경·장애물 거리·45→60→0°·현재 목표 좌표 변경, IMU 원본406개·GPS 원본45개·라이다 원본45개·제어 판단49개와 DO4개 저장·ZIP 내보내기 확인. 선박에서 저장 폴더만 사용해 지도·그래프·보고서도 재생성했습니다. 시험 소유자의 WebSocket을 22초간 끊고 그 관찰 구간 중 SSH도 실제 종료한 조사에서 DO22개가 계속 기록됐습니다. SSH 종료는 관찰 구간 시작 후에 실행했으므로 SSH 자체의 단절 시간을 22초로 계측한 것은 아닙니다. 모든 검증에서 실제 추진 명령 발행 증가0회입니다. 클릭 위치의 시험 기록을 실제 GPS 주행 자료와 구분합니다.

GPS 메시지는 수신하나 상태 -1·좌표NaN으로 유효한 위치가 없습니다. IMU는 기존 YAML 노드 이름 불일치로 출력이 비활성화돼 있어 해당 노드 이름으로 수신을 확인했고, 주행용 브링업에는 동일 센서 설정을 모든 노드 이름에 적용하는 `config/mechaship_imu.yaml`을 연결했습니다. 임시 `isabel-sensor-check.service`는 GPS·IMU·라이다만 읽고 액추에이터를 활성화하지 않습니다. 주행용 base 서비스 시작 시 이 진단 서비스를 먼저 중지하도록 충돌 관계를 설정했습니다.

최종 상태는 실제 GPS 모드·조사 대기·추진 비활성입니다. 실제 선체 이동·조향 부호·라이다 장착 방향·충돌 회피 성능·모터 중립 ACK는 물리 시험하지 않았습니다. 선박 적용 이후에도 실제 화면 공유 WebM 녹화 검증은 별도입니다.

## 주행 중 실시간 변경

지도 높이는 화면에 따라 540~820px이며 세로 여백을 줄였습니다. 웨이포인트 마커를 드래그해 놓으면 현재 주행을 재시작하지 않고 그 좌표를 적용합니다. 현재 목표를 옮기면 새 좌표로 즉시 재조향하며, 미래 목표를 옮기면 해당 목표 순서에서 사용합니다. 도착 후 관측 중인 목표를 멀리 옮기면 그 지점으로 다시 이동합니다. 직사각형의 생성된 셀 경로·격자 크기·조사 방식은 주행 전 설정입니다.

추진 출력(0~100%), 도착 반경(1~20m), 지점 관측(3~120초), 지그재그 각도(0~80°)은 입력 중 약 180ms 동안 추가 입력이 없으면 전송하고, 선박 제어의 다음 주기(기본 100ms)에 사용합니다. 네트워크 지연은 추가됩니다. 입력한 각도나 거리 값은 기록과 경유지 진행을 초기화하지 않습니다. 변경은 저장 확인 후 적용하며 전후 값과 시각을 events.jsonl에 남깁니다. 종료 이전의 지연된 변경·오래된 버전의 변경을 거부하고, 재접속하면 선박의 최종 설정과 경유지를 다시 받습니다. 오프라인 입력은 자동 재전송하지 않습니다.

지그재그 기본 각도는 45°입니다. 60°는 목표 방위에서 좌우 60° 진행으로 좌우 폭이 커지고 같은 선속에서 목표 방향 전진 성분이 줄어듭니다. 선회 속도를 60°/s로 지정하는 값은 아닙니다. 0°는 좌우 장애물 전환 없이 현재 목표 방위를 매 제어 주기 추종합니다. 현재 방향 전환은 + 키로만 요청합니다.

지점 관측이 3초라면 웨이포인트에 도착한 뒤 추진 0%·조향 중앙 상태에서 3초간 DO를 기록하고 다음 지점으로 갑니다. 기본 설정은 10초이며 자율운항 지그재그에는 관측 대기를 사용하지 않습니다. 조절하는 주행 출력은 추진 비율이며 목표 속도(m/s) 제어가 아닙니다. 지도 위 GPS 속도는 연속 두 GPS의 좌표와 센서 시각으로 계산한 추정값입니다.

## 두 주행 버튼

주행 시작과 동시에 선박의 `/home/ubuntu/water_survey_data/<조사ID>/`에 자동 기록합니다. 사진·영상 버튼, 노트북, SSH 연결과 독립적으로 저장하며 이전 조사는 자동 삭제하지 않습니다. 화면의 최근 600개 제한은 그래프 표시용이며 파일 기록 수를 제한하지 않습니다.

자동 기록에는 모든 수신 GPS·IMU·LaserScan 메시지의 원본 필드(`gps_raw.jsonl`, `imu_raw.jsonl`, `lidar_raw.jsonl`), 해석한 위치·방향·180개 라이다 구간, DO와 위치를 결합한 전체 `samples.csv`, 매 제어 주기의 `navigation.jsonl`, 실제 발행한 `commands.jsonl`, 시작·전환·종료 이벤트 및 주행 설정·경유지·범위·좌표 원점이 포함됩니다. IMU를 시간 구간별로 줄이지 않으며 라이다 원본 ranges/intensities도 남깁니다. 정지 뒤 약 2초 동안 발행하는 중립 명령도 같은 조사에 기록합니다. Bluetooth 원시 송수신 로그는 상위 `sensor_raw/`에 따로 보존합니다. 기록 범위는 이 대시보드가 구독·수신한 센서이며 카메라 영상이나 별도 PointCloud2를 자동 녹화한다는 뜻은 아닙니다.

각 기록은 줄마다 파일로 쓰고 약 1초 주기로 디스크에 동기화하며 정상 종료 때 최종 동기화합니다. 갑작스러운 전원 차단은 마지막 기록 일부가 손실될 수 있습니다. 저장 오류가 나면 조사를 종료하지 않고 중립으로 대기합니다. 저장 동기화가 복구되면 주행을 이어갑니다. 원본 파일은 보존하고, 재시각화 시 전원 차단으로 잘린 CSV 마지막 행은 제외한 사실을 메타데이터에 남깁니다.

저장된 조사 폴더만 있으면 선박 연결·ROS·브라우저 없이 다시 지도와 그래프를 만들 수 있습니다. 선박에서는 `ros2 run water_survey survey_rebuild /home/ubuntu/water_survey_data/<조사ID>`를 실행합니다. 복사한 소스와 조사 폴더가 있는 PC에서는 아래처럼 실행합니다.

```powershell
$env:PYTHONPATH='water_survey'
python -m water_survey.replay "D:\조사자료\<조사ID>" --output "D:\조사자료\시각화"
```

기본 출력은 조사 폴더의 `visualization/`입니다. `report.html`, DO 격자와 전체 위치 궤적을 겹친 `map.svg`, `timeseries.svg`, `track.geojson`, 그 밖의 분석 CSV/GeoJSON과 원본 기록을 포함한 `survey-export.zip`을 만듭니다. 배경 지도 타일은 포함하지 않습니다. 이 기능의 선박 적용과 저장 폴더 기반 재생성을 확인했습니다.

- **웨이포인트 주행**: 기존 동작 그대로, 찍은 순서의 지점으로 직접 진행합니다. 도착 반경 안의 새로운 GPS 두 번을 확인하면 추진 0·조향 중앙으로 전환하고 설정 시간 동안 관측한 뒤 다음 지점으로 이동합니다. 마지막 지점에서는 중립으로 대기하며 기록은 계속합니다. 직사각형 격자 모드도 이 버튼으로 기존 셀 중심 경로를 순서대로 관측합니다.
- **자율운항 주행**: 현재 IMU 방향에 가까운 쪽에서 시작해 목표 방위의 입력 각도를 추종합니다. 대시보드에서 + 또는 방향 전환 (+) 버튼을 누를 때마다 반대쪽으로 즉시 바꿉니다. 라이다 감지와 전환 시간 대기는 사용하지 않습니다.
- 자율운항은 중앙 안내점의 도착 반경 안에 들어오거나 해당 안내점의 중심선 수직 단면을 통과한 새 위치 두 번을 확인하면 멈추지 않고 다음 안내점으로 넘어갑니다. 마지막 안내점은 도착 반경 안의 새 위치 두 번을 확인해야 하며, 옆으로 단면만 통과해서 끝내지 않습니다. 도착 뒤 중립으로 대기하며 조사는 유지합니다. 따라서 이 모드의 안내점 통과는 그 좌표를 직접 방문했다는 뜻이 아닙니다.
- **주행 종료**: 현재 주행을 해제하고 조향·추진 발행자가 있으면 조향 90°와 추진 0%를 즉시 발행합니다. 같은 중립 명령을 약 2초간 반복합니다. 만료된 WebSocket 세션과 브링업 처리 중에도 같은 출처의 종료 요청을 받습니다. 종료 전에 보낸 지연된 시작 요청은 제어 버전으로 거부합니다.

제어 인터페이스는 `/actuator/key/degree`와 `/actuator/thruster/percentage`의 **조향 1개·추진 1개**입니다. 별도 좌우 스러스터 제어라고 가정하지 않습니다. 조향과 추진 메시지의 발행은 확인할 수 있지만 현재 토픽에는 모터 중립 ACK가 없어 물리적 정지를 소프트웨어 응답만으로 확정하지 않습니다.

## 라이다 장애물 판정

1. 기본 입력은 `sensor_msgs/LaserScan`의 `/scan`입니다. ROS 매개변수 `scan_topic`, `scan_yaw_offset_deg`로 실제 토픽과 선수 기준 장착 방향을 맞춥니다.
2. 전방 `[-90°, 90°)`를 1°씩 180개 구간으로 나눕니다. 각 구간의 유효한 양수 히트 거리값을 정렬하고 양 끝에서 각각 `floor(N × 0.2)`개를 제외한 나머지의 평균을 계산합니다.
3. 실제 전환 판단용 정면 1°는 선수 양쪽을 대칭으로 보는 `[-0.5°, +0.5°)`입니다. 이 구간에도 같은 양끝 20% 절사 평균을 사용하며 **평균이 설정한 인지 거리(기본 2m) 이하이면 장애물**입니다. 전방 180° 전체의 평균이나 최솟값으로 판정하지 않습니다.
4. 점이 5개 미만이면 정수 개수 절사 결과가 0개일 수 있습니다. NaN·0·음수·센서 범위 밖 값은 제외하고, `+inf` 무반사 광선은 숫자 평균에 넣지 않습니다. 유효한 정면 광선이 있으나 히트가 없으면 해당 프레임은 장애물 미검출입니다.
5. 한 장애물로 매 제어 주기마다 좌우가 뒤집히지 않게, 새 반사 프레임에서만 전환합니다. 최소 전환 간격(기본 3초)이 지난 뒤 장애물이 감지되면 다시 전환합니다. IMU 정렬이나 미검출 스캔을 기다리지 않습니다. 시간만으로 방향을 바꾸지는 않습니다.

이 방식은 요청한 강변 감지 기반 조사 전략이며 선체 전체의 충돌 없는 궤적을 계산하는 회피 계획기는 아닙니다. 실제 이동한 위치만 격자를 채우므로 하천의 모든 칸 관측을 보장하지 않습니다. 빈 칸은 계속 미관측으로 남습니다.

## 실행과 전체화면 창

기존 항법 작업공간을 덮어쓰지 않고 설치합니다.

```bash
sudo apt-get install bluez python3-aiohttp
mkdir -p /home/ubuntu/water_survey_ws/src
cp -a water_survey /home/ubuntu/water_survey_ws/src/
source /opt/ros/jazzy/setup.bash
cd /home/ubuntu/water_survey_ws
colcon build --packages-select water_survey
source install/setup.bash
ros2 launch water_survey dashboard.launch.py
```

지속 실행은 `water-survey-indoor.service`를 사용합니다. 이름은 호환용으로 유지하지만 현재 내용은 `dashboard.launch.py`를 실행하고 실제 위치 모드로 대기합니다. 대시보드가 `water-survey-base.service`를 시작/종료하며, 실제 조사는 별도의 주행 버튼으로 시작합니다. 기본 추진 20%, 설정 상한 100%입니다.

```bash
sudo install -m 0644 water_survey/deploy/*.service /etc/systemd/system/
sudo install -m 0440 water_survey/deploy/water-survey.sudoers /etc/sudoers.d/water-survey
sudo visudo -cf /etc/sudoers.d/water-survey
sudo systemctl daemon-reload
sudo systemctl enable --now water-survey-indoor.service
```

기존 선박 브링업과 `field.launch.py`를 같은 장비에 중복 실행하지 않습니다. `water-survey-base.service`는 부팅 자동 시작을 설정하지 않습니다. 하드웨어 출력이 없는 기존 `indoor.launch.py`도 유지합니다.

노트북에서는 다음을 실행하면 localhost 프록시와 **Chrome/Edge 독립 앱 창**을 열며 전체화면으로 시작하도록 요청합니다.

```bash
python water_survey/scripts/laptop_viewer.py --ship http://현재선박IP:8000
```

기본 주소는 `http://localhost:8787`입니다. `--windowed`는 일반 크기의 독립 창, `--no-browser`는 프록시만 실행합니다. `--browser`에 기존 Chrome/Edge 실행 파일 경로를 줄 수 있습니다. 지원 브라우저가 없으면 기본 브라우저로 열고 전체화면은 F11로 전환합니다. 노트북 프록시 종료와 선박 프로세스 종료는 서로 다릅니다.

SSH·브라우저가 끊겨도 선박 내부 조사와 파일 기록은 계속하며 재연결 시 같은 조사 상태를 받습니다. 선박 프로세스 재시작·전원 재부팅 뒤에는 기록을 남기고 새 대기 상태로 시작합니다. GPS 3초·IMU 2초·DO 5초 이상 지연되면 조사를 유지하고 추진·조향 중립으로 대기합니다. 현재 + 키 전환 방식에서는 라이다 단절로 주행을 대기시키지 않습니다. 유효한 입력이 복구되면 같은 조사·경유지·전환 방향을 이어갑니다. 사용자가 주행 종료한 뒤에는 센서 복구로 다시 출발하지 않습니다.

## 클릭 위치·직사각형·색 범위

**가상위치 퍼블리시**를 누른 뒤 클릭한 좌표만 입력됩니다. 자동으로 이동하지 않습니다. 주행 버튼으로 시작하면 추진 발행자를 만들며 `/gps/fix`를 덮어쓰지 않으며, 별도 `/water_survey/manual_fix`만 발행합니다. 조사 중에도 다음 클릭 위치를 줄 수 있습니다. 실제 GPS로 돌아갈 때는 정지 후 **위치 초기화**를 사용합니다.

직사각형의 두 꼭짓점을 지정하면 최대 2500칸의 셀 중심을 지그재그로 방문하는 별도의 격자 경로가 만들어집니다. 각 목표 칸에서 새 DO를 받아야 다음 칸으로 넘어갑니다. 범위 밖 DO도 원본 파일에는 남지만 격자에는 집계하지 않습니다. **새 조사 지도**는 화면을 새로 준비하고 기존 조사 파일은 보존합니다.

색 양 끝은 **현재 조사에서 누적된 격자 평균의 최솟값·최댓값**이며 2~12로 고정하지 않습니다. 모든 칸의 평균이 같으면 같은 중간색입니다. 원본 DO 범위는 별도로 보존합니다. 색은 DO 값의 상대 차이이며 오염 등급이 아닙니다.

## 데이터와 이미지 저장

상단 캡처·녹화 버튼은 제거했습니다. 주행 센서 데이터는 선박에 자동 저장하며, 격자·시계열 패널의 PNG 저장과 전체 조사 ZIP 내보내기는 사용할 수 있습니다.

## 파일과 다시 그리기

기록은 `/home/ubuntu/water_survey_data/`의 조사별 폴더와 `sensor_raw/`에 보존됩니다.

| 파일 | 내용 |
| --- | --- |
| `samples.csv` | DO, UTC 요청·수신 시각, GPS, 위치 출처, 경유지, IMU, 응답 시간, 원본 응답 |
| `mission.json`, `events.jsonl` | 경로·관측·주행 전략, 설정, 시작·방향 전환·중앙 안내점 통과·종료 |
| `gps.jsonl`, `imu.jsonl`, `lidar.jsonl`, `commands.jsonl` | 조사 중 실제 수신 정보와 발행 명령. 데이터가 있을 때 생성 |
| `grid.csv`, `grid.geojson`, `samples.geojson`, `route.geojson` | 관측 평균·최소·최대·개수와 좌표 도형 |
| `map.svg`, `timeseries.svg`, `report.html` | 좌표 기반 지도, 시간 그래프, 독립 보고서 |

DO에는 최근 2초 이내의 선박 수신 GPS를 결합합니다. 센서 내부 측정 시각·프로브 반응 지연·안테나/프로브 거리 보정은 하지 않습니다. 클릭 위치는 `position_source=simulated`, `experimental=true`로 구분합니다. 지도 배경 타일은 조사 ZIP에 복제하지 않습니다.

```bash
python water_survey/scripts/plot_csv.py samples.csv --output figures
PYTHONPATH=water_survey python -m unittest discover -s water_survey/tests -v
python water_survey/scripts/verify_click_survey.py --base http://localhost:8787 --output survey-check
```

마지막 명령은 **실제 DO가 들어오는 대시보드에 새 클릭 위치 시험 조사**를 만듭니다. 이미 진행 중인 조사가 있으면 건드리지 않습니다. 지속 WebSocket 읽기와 heartbeat로 연결을 유지하고, 실패하면 자신이 시작한 조사만 정지합니다. 실선박 연결 전의 로컬 fixture 검증과 실제 DO 검증은 별도로 기록합니다.

상세 운영 문서: [manual.html](water_survey/water_survey/static/manual.html). DO 단독 지도는 오염 배출원을 확정하거나 역추적하는 결과가 아닙니다.
