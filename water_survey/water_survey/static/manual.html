이사벨 위치별 용존산소 조사

갱신: 2026-11-25 · 웨이포인트 추종 / 강변 감지 좌우 45° 자율운항 / DO 격자 / 독립 창

1. 선박과 노트북 실행

이사벨의 마지막 확인 장비는 Radxa ROCK 5A / Ubuntu 24.04 / ROS 2 Jazzy이며 별개 kaboat2026 작업과 다릅니다. 대시보드 서비스 이름은 water-survey-indoor지만 현재 실행 내용은 실제 GPS 모드로 대기하는 dashboard.launch.py입니다. 브링업 시작/종료는 별도 water-survey-base.service만 제어합니다.

sudo systemctl start water-survey-indoor.service
# 노트북에서 독립 전체화면 창 실행
python water_survey/scripts/laptop_viewer.py --ship http://현재선박IP:8000

기본 노트북 주소는 http://localhost:8787입니다. --windowed는 일반 크기 독립 창, --no-browser는 프록시만 실행합니다. 기본 Chrome/Edge 앱 창에 전체화면 시작을 요청하며 F11로 전환할 수 있습니다. 실제 조사는 주행 버튼을 누르기 전까지 대기합니다.

2. 웨이포인트 추종과 직사각형 관측

웨이포인트 주행은 지정 지점으로 직접 이동합니다. 도착 반경 안의 새 GPS 두 번을 확인하면 조향 중앙·추진 0으로 관측하고 다음 지점으로 갑니다. 기본 관측 10초, 도착 반경 3m, 추진 20%이며 최대 설정은 30%입니다.

직사각형 전체 격자를 선택하고 두 꼭짓점을 찍으면 최대 2500개 셀 중심 경로를 만듭니다. 목표 칸에서 새 DO를 받아야 관측을 완료합니다. 범위 밖 측정은 원본 파일에는 남기고 격자에서는 제외합니다.

3. 강을 따라 좌우 45°로 자율운항

강 중앙의 진행 방향을 안내할 점들을 순서대로 지정하고 자율운항 주행을 누릅니다. 안내점 방위 기준 오른쪽 45°로 시작해 그 방위를 유지하여 직진하고, 정면 장애물 조건에 도달할 때만 반대쪽 설정 각도(기본 45°)로 바꿉니다. 일정 거리·시간 후 방향을 바꾸거나 중앙 방향으로 정해진 거리를 직진하는 구간은 없습니다.

중앙 안내점 반경에 들어오거나 그 안내점의 중심선 수직 단면을 통과한 새 위치 두 번을 확인하면 정지하지 않고 다음 점을 사용합니다. 마지막 안내점 구간 통과 후 중립 종료합니다. 실제로 안내점 좌표에 도착했다는 뜻과 구분합니다.

지도 점선은 중앙 경유지, 초록 선은 기록된 이동, 주황 짧은 선은 현재 목표 방위입니다. 실제 DO와 위치가 결합된 칸만 색이 채워지며 전 수역의 모든 칸 관측을 보장하지 않습니다.

4. 정면 1°의 라이다 판정

기본 입력은 /scan LaserScan입니다. scan_topic과 scan_yaw_offset_deg 매개변수로 실제 토픽과 선수 방향을 맞춥니다. 전방 [-90°,90°)는 180개의 1° 구간으로 나누고 각 구간에서 유효 거리값의 작은 쪽·큰 쪽 각각 floor(N×0.2)개를 제거해 평균을 구합니다.

실제 전환 판정은 선수 대칭 [-0.5°, +0.5°) 정면 1°의 절사 평균이 2m 이하일 때입니다. 전방 180° 전체 평균이나 최근접 점 하나로 판정하지 않습니다. 5점 미만이면 절사 개수가 0일 수 있습니다. 무반사 +inf는 수치 평균에서 제외하고, NaN·0·음수·범위 밖 거리도 제외합니다.

동일 장애물로 좌우가 연속 뒤집히지 않게 새 스캔에서만 전환하고, 최소 전환 간격 후 정면 장애물 감지 때 다시 전환합니다. 정렬·미검출 이력 조건은 없습니다. 이는 지정된 조사 전략이며 선체 전체의 충돌 없는 궤적을 계산하는 계획기는 아닙니다.

5. 주행 종료와 연결 단절

주행 종료은 세션이 만료돼도 같은 대시보드 출처에서 요청할 수 있습니다. 실제 추진 발행자가 있으면 추진 0%·조향 90°를 즉시 발행하고 약 2초 반복합니다. 늦게 도착한 예전 시작 요청은 거부합니다. 현재 물리 인터페이스는 조향 1개와 추진 1개이며 좌우 스러스터라고 가정하지 않습니다.

화면의 중립 발행은 전송 요청 확인이며 하드웨어 ACK나 실제 모터 정지 확인은 아닙니다. 선박 네트워크가 끊겨 요청이 전달되지 않으면 전달 미확인으로 표시합니다.

SSH·대시보드 단절만으로는 선박 조사를 멈추지 않고, 재연결 시 같은 조사 상태를 받습니다. GPS 3초·IMU 2초·DO 5초 이상 지연되면 조사는 유지하고 추진 중립으로 대기합니다. 정면 라이다 일시 누락은 마지막 유효 관측을 최대 1초만 사용하고 이후에는 중립 대기합니다. 유효 센서가 복구되면 같은 조사를 이어갑니다. 프로세스/전원 재시작 후 자동 출발은 하지 않습니다.

6. 클릭 위치와 지도 초기화

가상위치 퍼블리시를 누른 뒤 클릭한 좌표만 입력됩니다. 자동으로 이동하지 않습니다. 주행 버튼은 실제 추진기를 사용합니다. 위치 입력은 /gps/fix를 덮어쓰지 않고 /water_survey/manual_fix만 발행합니다. 조사 중에도 다음 클릭 위치를 지정할 수 있습니다.

위치 초기화는 정지 후 실제 GPS 수신으로 돌아갑니다. 새 조사 지도는 새 계획을 준비하되 기존 조사 폴더를 지우지 않습니다. 클릭 위치의 조사 파일은 simulated/experimental 표시를 유지하므로 현장 자료와 구분합니다.

7. DO 격자와 파일

색 양 끝은 현재 조사에서 누적된 격자 평균의 최솟값·최댓값입니다. 2~12mg/L 고정 범위가 아닙니다. 전부 같은 값이면 같은 중간색이며, 원본 DO 범위는 따로 보존합니다. 빈 칸은 미관측이고 보간하지 않습니다. 색은 DO 값의 상대 차이이며 오염 등급이 아닙니다.

기록 폴더는 /home/ubuntu/water_survey_data/입니다. ZIP에는 samples.csv, mission.json, events.jsonl, grid.csv/GeoJSON, samples/route.geojson, map.svg, timeseries.svg, report.html과 수신된 GPS·IMU·라이다·발행 명령 기록이 들어갑니다. 지도 타일은 조사 ZIP에 포함하지 않습니다. 라이다 기록과 방향 전환 이벤트를 함께 보관합니다.

DO에는 선박 수신 시각의 최근 2초 이내 GPS를 결합합니다. 센서 내부 시각과 프로브 반응 지연·장착 거리 보정은 하지 않으며 교정값을 변경하지 않습니다. DO 하나로 오염원·배출자를 확정하지 않습니다.

python water_survey/scripts/plot_csv.py samples.csv --output figures

8. 자동 기록과 내보내기

상단 캡처·녹화 버튼은 제거했습니다. 주행 센서 데이터는 계속 선박에 자동 저장됩니다. 격자·시계열의 PNG 저장과 조사 ZIP 내보내기를 사용할 수 있습니다.

10. 화면 촬영과 독립적인 자동 기록

주행 시작과 동시에 선박의 /home/ubuntu/water_survey_data/조사ID/에 저장합니다. 사진이나 녹화를 누를 필요가 없으며 SSH·노트북 연결이 끊겨도 선박 프로세스에서 기록합니다. 화면의 최근 600개 제한은 파일에는 적용되지 않고 이전 조사를 자동 삭제하지 않습니다.

수신한 GPS·IMU·LaserScan의 모든 원본 필드와 라이다 거리·강도, 해석한 위치·방향·180개 구간, DO 전체 측정과 위치, 매 제어 주기의 진행 판단, 발행 명령, 전환·종료 이벤트, 경유지·범위·설정·선수 방향 보정값을 보관합니다. IMU 기록 간추림은 없습니다. 정지 뒤 반복 발행하는 중립도 기록합니다. 별도 카메라 영상이나 구독하지 않은 PointCloud2 기록은 포함하지 않습니다.

약 1초마다 디스크 동기화하고 정상 종료 때 최종 동기화합니다. 전원 급차단 때 마지막 일부 기록 손실 가능성은 남습니다. 저장 오류면 조사는 유지하고 중립으로 대기하며 저장 복구를 기다립니다.

선박에서는 다음 명령으로 저장 폴더만 사용해 보고서와 지도·그래프를 다시 생성합니다.

ros2 run water_survey survey_rebuild /home/ubuntu/water_survey_data/조사ID

결과는 조사 폴더의 visualization/에 report.html, map.svg, timeseries.svg, track.geojson, 분석 CSV/GeoJSON, 원본 포함 survey-export.zip으로 저장됩니다. 원본은 덮어쓰지 않습니다. map.svg에는 DO 격자와 전체 위치 궤적이 겹쳐 표시되며 배경 지도 타일은 포함하지 않습니다. 노트북으로 원본 폴더를 옮긴 뒤에도 소스의 water_survey.replay 모듈로 생성할 수 있습니다.

11. 주행 중 경유지·설정 변경

지도 마커를 드래그해 놓으면 선박에 바로 전송합니다. 현재 목표는 새 위치로 재조향하고, 미래 목표는 순서를 유지합니다. 주행을 재시작하거나 이미 쌓인 DO 격자를 지우지 않습니다.

주행 출력·도착 반경·관측 시간·장애물 인지 거리·지그재그 각도는 입력 후 약 180ms 동안 추가 입력이 없으면 전송하고 다음 제어 주기에 적용합니다. 연결 지연은 별도이며 화면의 적용 완료 표시를 확인합니다. 연결이 끊겼을 때 입력한 값은 자동 재전송하지 않습니다. 격자 크기·범위·조사 방식은 주행 전에 설정합니다.

장애물 거리 기본 2m, 각도 기본 45°입니다. 60°는 목표에서 좌우 60°로 더 넓게 진행하며 목표 방향 전진 성분이 줄어듭니다. 각도 0°는 좌우 전환 없이 현재 목표를 직접 추종합니다. 이 각도는 선회 속도 설정이 아닙니다.

지점 관측 3초는 웨이포인트 도착 뒤 추진 중립으로 DO를 기록하는 3초 대기입니다. 지그재그 자율운항에서는 이 대기를 사용하지 않습니다. 주행 출력(%)과 GPS로 계산한 실제 속도 추정(m/s·km/h)은 별도로 표시합니다. 변경 시각과 전후 값은 조사 이벤트에 저장합니다.

12. 선박 적용 확인

2026-11-25 이사벨에 새 버전을 설치하고 빌드·자동 확인43개, 실제 DO·IMU·라이다 수신, 무추진 클릭 위치 조사, 주행 중 변경·저장·재시각화·SSH 단절 중 기록을 확인했습니다. 모든 시험에서 실제 추진 발행은0회입니다. 현재 실제 GPS 위치는 미확정이며 실제 위치 주행은 준비 조건을 충족하지 않습니다. 화면 공유 WebM 녹화와 실제 수상 회피 성능은 별도 검증 사항입니다.

13. 수동 GPS + 실제 추진

가상위치 퍼블리시는 GPS 입력만 바꿉니다. 주행을 시작하면 실제 IMU·라이다·서보·추진기가 작동합니다. 주행 시작 버튼이 실제 추진을 활성화합니다. 종료하면 수동 GPS에서도 추진 중립을 반복합니다.

지도는 Esri 위성영상입니다. 수영강 원본19단계 타일을 22단계까지 확대합니다. 화면 선박 좌표는 클릭 위치이며 실제 선체가 움직여도 자동으로 GPS 좌표가 따라 움직이는 것은 아닙니다.

최신 확인: 전체 브링업 후 수동 GPS로 실제 추진10%를 약1초 시험하고 중립으로 종료했으며 사용자가 회전을 확인했습니다. 주행 시작 버튼은 항상 실제 추진기를 사용합니다. 당시 시험은 중립으로 종료하고 기존 경로와 설정을 복원했습니다.

14. 센서 상태·지도·전체 브링업

상단 GPS에는 실제 제어에 사용하는 좌표를 표시합니다. 수동 GPS도 같은 위치 입력으로 표시하며 출처만 구분합니다. 라이다는 정면 거리와 점 수, IMU는 방위·자세·수신률과 주행 중 방위 오차를 보여줍니다. 화살표는 실제 IMU 방향을 따르고 현재 위치로 버튼은 확대 배율을 유지합니다.

전체 브링업·재시작 버튼은 중립 후 기존 관리 구동과 같은 사용자의 중복 mechaship_bringup 트리를 정리하고 새로 실행합니다. 처리 중 중복 요청은 막습니다. 2km 거리 제한은 제거했고 화면 세로 여백을 줄였습니다.

15. 북쪽 기준과 새 지도

브링업 첫 IMU 방향은 북쪽0°입니다. 이후 상대 회전으로 조향하고 지도 화살표를 갱신합니다. 새 조사 지도는 현재 수동 GPS 위치를 유지하고 그 지점을 중심으로 사용합니다. 주행 버튼은 실제 추진기만 사용하며 화면 설명과 선택 체크박스는 제거했습니다.

16. 연속 벽 감지와 전환 간격

정면 1° 절사 평균이 기본 2m 이하일 때 목표 방위 반대쪽 설정 각도로 전환하고, IMU로 현재 목표 방위에서 입력 각도만큼 벗어난 방위를 추종합니다. 정면 거리 조건과 최소 전환 간격만으로 다시 전환합니다. IMU 정렬이나 미검출 이력을 요구하지 않습니다. 좌우 전환 최소 간격은 기본 3초이며 입력 중 실시간 적용됩니다. 시간만으로 꺾지는 않습니다.

센서 누락이나 도착으로 조사 파일을 자동 마감하지 않습니다. 센서 지연은 중립 대기 후 복구 시 이어가고, 마지막 경유지는 반경 안에 실제로 들어온 뒤 중립으로 기록을 계속합니다. 주행 종료 버튼으로 종료합니다. 정지 후에는 센서가 복구돼도 재출발하지 않습니다.

17. NTRIP

계정은 선박의 비공개 ~/.config/isabel/ntrip.yaml에만 보관합니다. 선택 위치는 VRS 초기 위치에 사용하며 실제 /gps/fix를 덮어쓰지 않습니다. RTCM 보정 수신은 확인했으며 실제 GPS 수신기의 RTK FIX는 아직 확인되지 않았습니다.

18. 목표 접근·시작 방향·입력값 저장

처음에는 좌우 목표 방위 중 현재 IMU 방향에 가까운 쪽을 택합니다. 이동 중에는 현재 목표 방위에서 입력 각도만큼만 벗어나도록 갱신하며 가까워져도 각도를 늘리지 않습니다. 도착 반경에 도달하면 조사는 유지하고 중립으로 대기합니다.

입력창의 Enter는 즉시 적용하며 선박 settings.json에 저장합니다. 새 지도·프로세스 재시작 후에도 입력값을 유지합니다. 지도 축척은 노트북 브라우저에 저장해 새 지도·새 창에서 같은 배율로 복원합니다.
