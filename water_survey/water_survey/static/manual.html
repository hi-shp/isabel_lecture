수영강 위치별 용존산소 조사

웨이포인트 순차 이동 · 실제 DO 연속 수신 · 격자 지도 · 독립 실행 및 파일 기록

구현일: 2026-11-04. 선박: mechaship-4rvcev / Radxa ROCK 5A / Ubuntu 24.04 / ROS 2 Jazzy. 센서: ScienceCube WL118DO, WL118D283, V403.

실내 시험과 현장 기록은 구분됩니다. 가상 GPS 모드는 실제 DO에 가상 좌표를 붙여 소프트웨어를 시험합니다. 실제 수영강 수질 분포를 측정한 결과가 아닙니다. DO가 낮은 지점은 추가 조사 후보이며, DO 하나만으로 오염원이나 배출자를 확정하지 않습니다.

1. 켜기: SSH가 끊겨도 계속 실행

아래 서비스는 선박 내부에서 실행되므로 SSH, 노트북, 휴대폰 핫스팟 또는 대시보드 연결이 끊겨도 이미 시작한 조사와 파일 저장을 계속합니다. 센서 Bluetooth와 선박 GPS·IMU는 선박 내부에서 직접 처리됩니다.

실내 시험:

sudo systemctl start water-survey-indoor
# 대시보드: http://192.168.80.78:8000

수상 조사 브링업:

sudo systemctl start water-survey-field

두 서비스는 서로 배타적입니다. 수상 서비스를 시작하면 실내 서비스가 종료되고, 기존 Mechaship 센서 브링업과 새 대시보드가 함께 실행됩니다. IP는 핫스팟 재연결 시 바뀔 수 있습니다. 브라우저는 노트북에서 위 주소를 열면 됩니다.

# 서비스 상태 및 로그
systemctl status water-survey-indoor water-survey-field
journalctl -u water-survey-field -n 60 --no-pager
# 프로그램 종료 (SSH가 연결되어 있을 때)
sudo systemctl stop water-survey-field water-survey-indoor

실내 서비스는 현재 선박에서 부팅 자동 시작으로 설정되어 있습니다. 수상 서비스는 설치 후 수동 시작합니다. 새 통합 브링업은 ros2 launch water_survey field.launch.py이며, 설치된 기존 Mechaship 브링업과 대시보드를 함께 올립니다. SSH 종료와 무관하게 운용하려면 위 서비스 명령을 사용하세요. 서비스를 실행 중일 때 같은 launch를 별도로 중복 실행하지 마세요.

전원 꺼짐이나 프로세스 오류 후에는 진행 중 경로를 자동 재개하지 않습니다. 기록은 남지만 대시보드는 대기 상태로 돌아옵니다. SSH 단절과 선박 자체 재부팅은 다릅니다.

2. 실내 시험 순서

  1. DO 센서를 PC 모드로 켭니다. 윈도우 Science#과 휴대폰에서 동시에 연결하지 않습니다.
  2. 대시보드 상단에서 실제 DO 숫자와 수신 상태를 확인합니다.
  3. 가상 GPS 위치 찍기를 누르고 지도에 현재 위치를 지정합니다.
  4. 경유지 추가를 누르고 지도에 순서대로 점을 찍습니다. 지도 확대 후 가까운 점부터 시험하면 빨리 확인할 수 있습니다.
  5. 격자 크기, 지점 관측 시간, 가상 속도를 설정하고 순서대로 조사 시작을 누릅니다.
  6. 가상 선박이 순서대로 이동하고 지점마다 관측합니다. 하단 사각 격자는 그 칸에서 받은 DO의 평균으로 채워집니다.
  7. 현재 조사 파일 받기로 ZIP을 저장합니다. 가상 GPS 데이터에는 position_source=simulated가 기록됩니다.

실내 서비스는 추진 토픽 발행자 자체를 만들지 않습니다. 가상 GPS는 화면과 조사 프로그램 내부 위치에만 반영되며 실제 /gps/fix에는 발행하지 않습니다. 화면 하단의 추진 명령 발행 횟수는 0회여야 합니다.

3. 수상 조사 순서와 동작

  1. 수상 서비스를 시작하고 실제 GPS 모드를 선택합니다.
  2. 실제 GPS와 IMU, DO가 새로 들어오는지 확인합니다. 유효한 GPS가 없으면 시작할 수 없습니다.
  3. 수상 장애물과 통행을 고려해 경유지를 지정합니다. 첫 지점 기준 반경 2km, 최대 100개까지 허용합니다.
  4. 기본 추진 출력은 20%, 설정 상한은 30%입니다. 도착 반경 기본 3m, 관측 대기 기본 10초입니다. 프로브 안정화 시간은 실제 현장 반응을 보고 조정해야 합니다.
  5. 수상 주행 활성화를 확인하고 시작합니다. 두 번의 새로운 GPS 수신에서 도착 반경 안이면 추진을 0으로 하고 관측합니다. 관측 후 다음 지점으로 이동하며 마지막 지점 후 종료합니다.
  6. SSH와 브라우저 연결을 끊어도 계속됩니다. 다시 접속하면 현재 상태와 저장 기록을 볼 수 있습니다.

실제 GPS가 3초 이상, IMU가 2초 이상, DO가 5초 이상 갱신되지 않으면 조사를 정지합니다. 추진기 수신 노드가 없거나 다른 조향·추진 발행자가 나타나도 주행을 막습니다. 오류 후 자동으로 출발하지 않으며 원인 해결 후 새 조사를 시작합니다.

조향 방향과 실제 수상 주행은 현장에서 별도 확인이 필요합니다. 코드가 사용하는 물리 인터페이스는 조향 서보 1개와 추진 출력 1개입니다. 별도의 좌·우 추진기 토픽은 현재 조사한 사용자 코드와 설정에서 확인되지 않았습니다. MCU 내부 배선과 실제 추진기 구성은 이 소프트웨어 분석만으로 확정하지 않습니다. 이 구현에는 장애물 자동 회피나 유동장 기반 오염원 역추적 알고리즘이 포함되어 있지 않습니다.

4. 데이터와 격자의 의미

항목의미
DO / mg/L센서의 순간값을 1초마다 읽습니다. 체크섬과 값 범위를 검사하며 교정값은 변경하지 않습니다.
수신 시간선박의 UTC 요청·수신 시각. 센서 내부 측정 시각이 아닙니다. 화면은 브라우저 현지 시간으로 표시합니다.
위치 결합DO 수신 시점의 최근 GPS를 사용합니다. GPS 수신 후 2초 이내만 지도에 넣으며, 그렇지 않으면 DO 행은 저장하되 위치는 비웁니다.
격자첫 경유지를 기준으로 동서·남북 미터 좌표를 계산하고 일정 크기의 사각 칸에 평균·최소·최대·개수를 집계합니다. 빈 곳을 보간하지 않습니다.
색2~12 mg/L 고정 표시 범위. 범위 밖 색은 양 끝 색으로 표시하지만 실제 값은 그대로 저장합니다. 이는 오염 등급이나 법적 판정 기준이 아닙니다.
지연통신 왕복 시간은 기록하지만 프로브 반응 지연이나 GPS 안테나-프로브 거리 보정은 하지 않습니다.

DO는 온도·기압·염분·광합성·시간대 등의 영향을 받습니다. 수영강처럼 염분 변화가 있을 수 있는 조사에서는 염분 설정과 별도 수온·염분 측정, 반복 관측 및 기준 장비 비교를 함께 기록해야 합니다. 위도별 DO 차이만으로 배출원을 특정하지 않습니다.

5. 파일 전달과 다시 그리기

선박 기록 폴더: /home/ubuntu/water_survey_data/. 조사마다 새 폴더가 생성됩니다. 센서 원본 통신은 sensor_raw/에 별도로 연속 저장됩니다.

파일용도

mission.json경로, 설정, 좌표 기준, 조사 상태, 가상 위치 여부

events.jsonl시작, 경유지 도착, 종료 및 이유

대시보드의 PNG 저장 버튼으로 하단 격자와 그래프도 이미지로 받을 수 있습니다. 경로 저장/불러오기는 경유지 좌표와 설정을 JSON으로 교환합니다. 온라인 지도 타일은 ZIP에 복제하지 않으며, 내보낸 지도는 좌표 기반 도형 이미지입니다.

코드 묶음의 scripts/plot_csv.py로 CSV를 다시 PNG와 SVG로 그릴 수 있습니다. Python과 matplotlib가 설치된 컴퓨터에서 실행합니다.

python plot_csv.py samples.csv --output figures

6. 기존 선박과 연결

이 저장소는 water_survey 패키지를 추가합니다. 원래 ROS 패키지는 별도로 설치되어 있어야 합니다. field.launch.py는 설치된 mechaship_bringup을 포함하고 대시보드 하나를 함께 실행합니다. 기존 gps_map_node와 다른 항법 프로그램은 같은 포트·추진 토픽을 사용하므로 동시에 실행하지 않습니다.

현재 확인한 물리 인터페이스는 /gps/fix, /imu, /actuator/key/degree, /actuator/thruster/percentage입니다. 조향 중심 90°, 범위 30~150°를 사용하며 실제 조향 방향과 수상 주행은 아직 검증하지 않았습니다. 좌우 독립 추진기가 별도 토픽을 사용하는 배선이면 이 인터페이스에 맞는 추가 어댑터가 필요합니다. MCU 펌웨어는 변경하지 않았습니다.

7. 센서 꺼짐과 연속 수집

대시보드 서비스는 조사 시작 전에도 1초 간격의 읽기를 계속 수행합니다. Bluetooth가 끊기면 다시 연결을 시도합니다. 센서 자체 전원이 꺼졌다면 화면에 연결 끊김을 표시하며, 사람이 전원을 켜야 할 수 있습니다. 공개 WL118DO 설명서에서 자동 절전 시간과 무선 전원 켜기 기능은 확인하지 못했습니다. 연속 읽기가 자동 꺼짐을 항상 막는다고 보장하지 않습니다.

8. 연구 결과에 쓸 수 있는 표현

현장 주행과 센서 검증을 완료한 후에는 “사전에 지정한 경유지를 순차적으로 자율 주행하며 위치별 용존산소를 수집하고, 격자 평균 분포로 저산소 관측 지점을 식별했다”처럼 측정한 범위를 명확히 표현하세요. 현재 실내 시험만으로 “수영강 오염원을 자율 추적·규명했다”라고 결론 내릴 수는 없습니다.
